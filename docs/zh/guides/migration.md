# 从旧版 CLI 迁移

BYF 是新一代终端 agent，也是一次全新起点。如果你之前在使用上一代旧版 CLI，不必从头开始：一条命令即可把你的配置、MCP 服务器和会话历史迁移到新版本。

## 为什么要迁移

byf 不再依赖 Python 或 `uv` 工具链，安装与升级都更简单。它开箱即用提供原生 compile 二进制（GitHub Release 或 npm optionalDependencies）——终端用户无需预装 Bun 或 Node 即可运行 CLI。

终端 UI 也经过了重新设计，体验更轻快。

旧版 CLI 正在过渡到 byf，迁移后你可以沿用既有配置与会话历史。

## 如何迁移

有两种迁移方式。

**安装 byf 后首次运行 `byf`** 时，它会自动检查 `~/.byf/` 下是否存在旧版 CLI 数据。若检测到，会弹出迁移提示，你可以选择「现在迁移」「稍后再说」或「不再询问」。

你也可以**随时手动运行**：

```sh
byf migrate
```

你可以选择是否一并迁移聊天会话。如果暂时不需要历史记录，选「仅配置」即可；否则选「配置 + N 个会话」一次全部迁移。结束时会打印汇总信息。

## 迁移过程中会发生什么

**会迁移的内容**：配置（`config.toml`）、MCP 服务器配置、输入历史，以及你选择迁移的聊天会话。

**不会迁移的内容**：OAuth 登录凭据和 MCP 服务授权不会被复制，因此迁移后你需要重新执行 `/login` 并重新授权 MCP 服务器。旧版 CLI 的插件也不在迁移范围内。

::: tip
迁移**绝不会修改或删除** `~/.byf/` 下的任何旧数据。旧版 CLI 仍像以前一样工作，两者互不干扰。迁移也可以重复执行——已经迁移过的会话不会被重复导入。
:::

迁移后，从旧版 CLI 导入的会话在会话选择器中会带有 `[imported]` 标记，以便与新建会话区分。
